# 自动指法建议：它是怎么算出来的
# How the automatic fingering suggestion works

代码：`src/fingering.ts`（约 150 行，TypeScript，**没有用任何第三方库、没有联网、没有机器学习模型**，全部在设备上计算，所以离线可用，也没有授权问题）。
Code: `src/fingering.ts` — about 150 lines, no third-party library, no network, no machine-learning model; it runs on the device (works offline, no licence issues).

> 它是**参考建议**，不能代替老师。App 里显示为蓝色数字；乐谱里已经有的指法、以及你自己标注的指法**永远优先，不会被改动**。
> It is a *suggestion for reference*, not a replacement for a teacher. Fingerings already printed in the score, and the ones you enter yourself, always win and are never changed.

## 1. 输入 / Input
- 每个音符：音高（MIDI 号）、小节、小节内位置、所属声部和**手**。
- **哪只手**：看这个音符所在谱表的谱号——低音谱号（F）= 左手，其余 = 右手。（所以一份只有一个谱表的谱子，会整份按右手算。）
- 跳过：连音线的后一个音（和前一个同指）、装饰音。

## 2. 把音符分成“线条”和“和弦” / Lines and chords
同一只手、同一时刻同时响的音 = **和弦**；其余按时间顺序连成**单音线条**。线条遇到和弦就在此断开，分段计算。

## 3. 单音线条：动态规划（Viterbi）/ Single-note lines
目标：给一段音符选 1–5 指，使**总代价最小**。每个音符有 5 种候选，相邻两个音之间有“转换代价”，每个音自己也有“个体代价”。用动态规划（每一步只保留到达每个手指的最小代价）求全局最优，复杂度 O(n×5×5)。已有指法的音符，候选只有那一个，其余音符围绕它优化。

**个体代价（unary）** —— 黑键上避免拇指和小指：
- 黑键用 1 指：+1.0；黑键用 5 指：+0.6。

**转换代价（transition）** —— 从音 1（手指 f1）到音 2（手指 f2），按手的方向把手指编号换成“位置”（右手 1→5 随音高升高；左手相反）：
- **同音重复**：同指 0.5，换指 1.2。
- **大跳（超过 9 个半音）**：手需要重新定位，基础 2.5；如果手指顺着跳的方向（如右手向上跳用 1→5）减 0.5，否则加 0.5。
- **同一手位内（手指位置顺着音高方向，不交叉）**：每对手指有一个舒适的音程范围（半音数）：
  - 间隔 1/2/3/4 个手指位：最小 `[1, 3, 5, 7]`，最大 `[3, 5, 8, 10]`（数组 `LO` / `HI`）。
  - 小于最小：每差 1 个半音 +1.5；大于最大：每多 1 个半音 +2.5，多出 3 个以上再 +10（几乎不可接受）。
  - **不同的音用同一个手指**：音程 ≤2 个半音 +4，否则 +7。
- **交叉（手指方向和音高方向相反）**：默认代价 50（基本被排除），只有两种经典动作例外：
  - **拇指在下穿过**（右手上行 / 左手下行，从 2、3、4 指换到 1 指）：`1.2 + 0.5×音程`，从 2 指穿过再 +1.5。
  - **越过拇指**（右手下行 / 左手上行，从 1 指换到 3、4 指）：`1.2 + 0.5×音程`。
  - 交叉音程超过 4 个半音再 +20；落在黑键上再 +1。

这些数值是**人工调出来的经验常数**（见下面的限制），不是从某个数据集学出来的。

## 4. 和弦：标准指法表 / Chords
按和弦里的音数，用教学中最常见的指法（右手，从最低音到最高音）：
| 音数 | 指法 |
|---|---|
| 2 个音 | 音程 ≤ 4 个半音：1-3；更宽：1-5 |
| 3 个音 | 1-3-5 |
| 4 个音 | 1-2-3-5 |
| 5 个音 | 1-2-3-4-5 |
左手：同一套指法**反过来**（最低音用最高的指号，例如 3 个音 = 5-3-1）。6 个音以上不给建议。如果和弦里有任何一个音已经有指法，整个和弦不再建议。

## 5. 已知限制（请如实告诉提问者）/ Limitations
- 是**规则 + 代价模型**，不是演奏数据学出来的，也没有和专业编订的指法集（如各版本的出版指法）做过系统对比验证。
- 不理解乐句、和声、句法与音乐表情；**不考虑手的大小**，没有个人化。
- 不处理多声部同时在同一只手里的复杂织体（它按“同一时刻的音 = 和弦”处理），不处理换指（同一个长音上换指）、指法的“替换指法”（如 3-2-1 同键换指）、滑指、五指位置的整体规划。
- 左右手只按谱号判断，一个谱表里混有两只手的织体会判断不准。
- 和弦用固定表，不看实际音程是否适合你的手。
- 因此它适合**给初学者一个合理的起点**；遇到专业的或特殊的段落，请以编订者的指法或老师的意见为准。

## 6. 思路来源 / Where the ideas come from
- 基本原则来自通用钢琴教学常识：五指位、拇指穿越与越指、避免在黑键上用拇指和小指、和弦用固定指型。
- 用“相邻音转换代价 + 动态规划”求最优指法，是计算机指法研究里常见的做法（例如 Parncutt 等人 1997 年的钢琴指法“人体工学模型”这一类研究）。本实现**是针对本 App 的简化原创实现，不是对某篇论文或某个软件的移植**，代价表里的数值是为了让常见的音阶、琶音、跳进得到合理结果而调整的。
